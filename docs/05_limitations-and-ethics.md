# 05. 한계점 · 윤리

- 버전: v0.1.0
- 최종 갱신: 2026-05-21
- 작성자: DATA

본 문서는 효돌 합성 어르신 데이터셋의 **구조적 한계**와 **사용 시 지켜야 할 윤리적 원칙**을 정리한다. 분석 결과를 보고서·논문·발표로 만들기 전 반드시 숙지.

---

## 1. 합성 데이터로서의 본질적 한계

### 1-1. 발견은 곧 "박은 패턴의 재발견"

본 데이터셋의 모든 통계적 패턴은 합성 모델이 의도적으로 박은 것이다. 학생이 발견하는 모든 상관·차이·트렌드는:

- ✅ "데이터 안에 그런 패턴이 존재한다"는 사실의 확인
- ❌ "현실 세계의 효돌 사용자에게도 같은 패턴이 있을 것"이라는 추론

이 둘은 다르다. **합성 모델이 박지 않은 패턴은 발견될 수 없다**. 예를 들어 본 데이터셋에는 "성별과 사용 패턴 간 상호작용"이 명시적으로 박혀 있지 않으므로, 그 분석은 noise만 보일 가능성이 크다.

### 1-2. 합성 모델의 가정과 한계

`docs/01_design-and-method.md` Section 4 참조. 주요 가정:

- 우울·고독·기능제약 점수는 연령·성별·혼인·가구형태에 **conditional independent**로 합성 (실제로는 더 복잡한 상호작용 존재 가능)
- 사용 패턴은 7종으로 한정 (실제 사용 패턴은 더 다양할 수 있음)
- 인지 능력 hidden state는 단일 잠재 변수 (실제는 다차원 — 기억·주의·실행기능 등)
- STT 인식률은 사용자별 단일 신뢰도 (실제는 발화 종류·환경·내용에 따라 변동)
- 대화 내용은 효돌 원본 782건과 LLM 합성 mix (LLM의 token bias 반영됨)

### 1-3. 통계적 검정의 의미

- t-test, ANOVA, 카이제곱 등 **모든 검정의 p-value는 의미 없음**. 표본이 합성이므로 "유의하다"는 결론은 합성 노이즈 수준 이상의 무엇도 의미하지 않음.
- 효과 크기(Cohen's d, η², r 등)는 합성 모델의 신호 강도를 반영하므로 데이터 내부 비교에는 유용
- 시각화·기술 통계가 가장 안전한 보고 단위

## 2. 효돌 원본 분포 가정의 한계

### 2-1. 효돌 원본 24명·단일 시점·단일 기관

본 합성 데이터셋의 분포 reference는:
- 인구통계: NVIDIA Nemotron-Personas-Korea (한국 통계청 등 실측 기반)
- 효돌 사용 패턴·점수 분포: **단일 주거복지 시설 24명**

따라서 효돌 원본의 분포가 한국 전체 60+ 어르신을 대표하지 않을 가능성이 매우 크다 (이중 취약성 — 경제적 + 연령 취약). 우리 합성 데이터는 그 편향을 그대로 또는 부분적으로 상속받았을 수 있다.

### 2-2. 효돌 효과성 사전·사후 변화의 reference

`docs/01_design-and-method.md` Section 4-5에서 사후 wave 합성에 사용한 reference는 효돌 브로셔 페이지 8의 사전·사후 비교 차트. 이 차트는 효돌 마케팅 자료의 일부이므로 효과 크기가 다소 과장되었을 가능성이 있다. 우리 데이터의 사전·사후 변화도 이를 그대로 반영하므로 **"효돌 효과성을 입증한다"는 결론은 부적절**.

## 3. 인지 측정 페어링의 한계

본 데이터셋의 핵심 신규 분석축인 `cognition_test_id` 페어링도 다음 한계가 있다:

| 측면 | 한계 |
|---|---|
| Window 크기 | 30초 고정 (실제 인지 측정은 더 다양한 window) |
| 응답 유형 | interaction 5종으로 한정 (실제는 더 다양 — 미세 표정·시선 등) |
| 인지 부하 | 단일 prompt 단위만 측정 (연속·복합 인지 부하는 측정 안 됨) |
| 환경 노이즈 | 합성에서 일정 비율 random missing 처리 (실제 환경 노이즈는 더 복잡) |
| Hidden state | 단일 잠재 변수 (다차원 인지 모델 아님) |

→ "인지 능력 측정의 가능성을 보여주는" 수준의 demo 데이터로 한정. 실제 인지 평가 도구로 사용 금지.

## 4. 사용 시 윤리적 원칙

### 4-1. 데이터 자체 보호

- ❗ **외부 재배포 금지** (수업·학술 목적 외): GitHub 공개 리포·SNS·블로그 게시 금지
- ❗ 분석 코드만 공개, 데이터 파일은 `.gitignore` 처리
- ❗ 학생 수업 종료 후 데이터 사본 삭제 권장 (보관 필요 시 암호화 저장소)

### 4-2. 분석 결과 보고 시

- ❗ 개별 user_id 노출 최소화 — 집계·군집·분포 단위로 보고
- ❗ 합성 데이터임을 보고서 첫 페이지에 명시
- ❗ 통계 결과는 "탐색적 해석"으로 한정. "유의하다"·"입증되었다" 표현 금지
- ❗ 외부 추론·일반화 금지 — "본 데이터셋 내부 패턴"으로 한정 기술

### 4-3. 외부 학술 출판·발표 희망 시

- 강사(고영혁)를 통해 ㈜효돌에 별도 정식 절차 경유
- 본 합성 데이터는 학술 출판용 1차 자료로 부적절. 원본 효돌 데이터 또는 추가 실측 데이터 확보 후 진행
- 합성 데이터로 도출된 가설을 실측 데이터로 검증하는 사용은 가능 (가설 생성 도구로서의 활용)

### 4-4. 효돌 또는 ㈜효돌에 관한 외부 진술

- 본 데이터의 분석 결과를 "효돌 서비스의 효과성·문제점"으로 외부에 진술 금지
- 효돌 마케팅·비판 어느 쪽으로도 사용 금지 — 합성 데이터의 결론은 그 어느 쪽도 입증·반증할 수 없음

## 5. 분석 안티패턴 체크리스트

학생이 분석 결과 보고서를 제출하기 전 self-check:

- [ ] 합성 데이터임을 보고서 첫 페이지에 명시했는가?
- [ ] "효돌이 ~한다"·"노인이 ~한다" 같은 일반화 진술을 피했는가?
- [ ] p-value 중심 보고를 효과 크기·시각화로 대체했는가?
- [ ] 개별 user_id 노출 없이 집계 단위로 보고했는가?
- [ ] "탐색적 분석"·"본 데이터셋 내부 패턴"이라는 한정 표현을 사용했는가?
- [ ] 분석 한계 섹션을 보고서에 별도로 작성했는가?
- [ ] 외부 일반화·인과 추론·정책 제안을 피했는가?
- [ ] 데이터 자체를 외부 공개 저장소에 업로드하지 않았는가?

## 6. 본 데이터셋의 "할 수 있는 것"·"할 수 없는 것" 요약

### ✅ 적합한 사용

- SQL·DuckDB·시각화 도구 학습
- 합성 데이터의 패턴 탐색 연습
- 가설 생성 (실측 데이터로 후속 검증 필요)
- 분석 워크플로우·도구 사용 연습
- LLM 협업 분석 워크플로우 학습 (Claude Code 등)
- 효돌 운영 시스템의 schema upgrade 청사진 탐색

### ❌ 부적합한 사용

- 효돌 서비스의 실제 효과성 평가
- 한국 노인 인구 모집단 추론
- 학술 출판의 1차 데이터
- 인과 추론 (RCT 아님)
- 임상적 의사결정
- 실제 인지 평가 도구
- 정책 제안의 근거

## 7. 데이터 품질 이슈 보고

분석 중 다음을 발견하면 강사에게 보고:

- 명백한 합성 오류 (예: 50세 이하 사용자, age_group 누락, NULL 일관성 깨짐)
- 비현실적인 값 분포 (예: 모든 사용자의 GDS = 0)
- 인지 측정 페어링 오류 (예: prompt event 없는데 cognition_test_id 존재)
- 효돌 원본 도메인 값과 불일치 (예: interaction_type에 정의되지 않은 값)
